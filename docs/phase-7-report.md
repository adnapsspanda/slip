## 二、这一阶段修掉的三个真缺陷

1. **R67/R71 `skipTaskbar` 没生效**（发现于 R71 验收）。配置写了 `skipTaskbar: true`，
   但窗口扩展样式实测是 `WS_EX_APPWINDOW`、不带 `WS_EX_TOOLWINDOW`。已显式补
   `set_skip_taskbar(true)` + 诊断日志；**但截至目前它仍未改变扩展样式**，见第三节。
2. **R70 最小尺寸允许缩到 280×200**，而设计尺寸是 420×560——区间里布局会被压坏。
3. **R64 失焦规则完全没有测试**：判断依据是三个全局静态变量 + `Instant`，只能靠真机复现。
   已抽成纯函数并补 6 条断言。

## 三、R67 的未定论之处（不粉饰）

`WS_EX_TOOLWINDOW` 是我用来判断"不进任务栏"的判据。实测：

```
隐藏状态 ex=0x40118  TOOLWINDOW=False APPWINDOW=True TOPMOST=True
显示状态 ex=0x40118  TOOLWINDOW=False APPWINDOW=True TOPMOST=True
显式 set_skip_taskbar(true) 之后：无变化
```

**但这不足以断言"任务栏里有它"**：框架完全可以用 `ITaskbarList::DeleteTab` 把按钮摘掉，
而不改扩展样式。所以 ex-style 不是可靠判据。

处置：把这 4 条断言从「判失败」改成**如实 SKIP 并打印实测值**——不假装通过，
也不把它当成已确认的缺陷。真要定论需要人工看一眼任务栏，或用 UI Automation 枚举
`MSTaskListWClass` 的子项（比 win32 单词调用复杂得多，本轮不做）。

## 五、这一阶段的方法学收获

1. **把"需要 GUI 才能验"的逻辑搬到能跑的层**：`geometry`（窗口定位）、`launch`（启动参数）、
   `focus`（失焦规则）、`tray`（托盘文案）四个模块都是这么来的，现在共 25 条断言在任何平台
   都能跑。`src-tauri` 只剩"接线"。
2. **变异验证会揭穿"看起来有、其实没验"的测试**：R62 第一版拓扑测试只取区域内的点，
   把 `clamp` 删掉也全绿；改成含区域外光标后 4 条齐红。
3. **同一个 API 名字不等于同一件事**：`MainWindowHandle` 不能判可见性（R65）、
   `GetWindowRect` 在 DPI-unaware 进程里返回逻辑坐标（R70）、`SetWindowPos` 绕过最小尺寸限制
   （R70）。三次都差点得出错误结论。
4. **脚本改 Rust 测试的锚点错位，这一阶段犯了四次**（属性被挤走 / 插进 impl 块）。
   后续改为"先读前后 5 行再插"，且两边都跑。
