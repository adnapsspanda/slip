## 二、四个"原来看起来没事、其实一直坏着"的地方

这几处不是审美调整，是真实缺陷：

1. **R39 的省略号从来没生效过**：`.paper__meta` 写了 `text-overflow: ellipsis`，但 flex 子项默认
   `min-width: auto`（等于内容宽度），它宁可不收缩也不省略。补 `min-width: 0` 才生效。
2. **R35 的两颗按钮等于没有焦点提示**：`:focus-visible` 只改 `opacity: 0.85`，而它们平时就是
   半透明，肉眼分辨不出 1 与 0.85 的差别。已改为 2px 实心焦点环。
3. **R40 的二次确认没有视觉警示**：恢复备份会覆盖当前内容，但确认态和普通按钮长得一样。
4. **R37 的诊断行会把文件名切碎**：`word-break: break-all` 改为 `overflow-wrap: anywhere`。

## 三、证据：已经验到的 / 还没验的

| 项 | 方式 | 结果 |

| 死样式审计 | 提取 CSS 类名，在源码里反查 | 0 个未被引用的类 |

### 未验证（不混进上表）

**CDP 计算样式断言**：R41 新增的 8 条断言已写进 `tools/cdp-probe.mjs`（`bun build` 解析通过），
覆盖 R32 发丝轮廓、R33 空态动效名、R35 焦点环宽度、R36 `scrollbar-width`、R38 质感层、
R39 省略号与 `min-width`。**但这一整轮 exe 都被 Smart App Control 拒绝执行**，探针跑不起来，
断言一次都没执行过。

也就是说：这些断言**存在但未证明能跑通**。它们第一次真正执行会发生在下面任一时机——
exe 被放行、或在没有 SAC 的机器上（CI）。

## 四、预算守线记录

R40 做完时 CSS 一度涨到 **10.10 KB，超了 R74 的 10 KB 预算**。处理方式是找冗余而不是改预算：

- `info` 档改为复用现有中性标记（`--paper-card` / `--paper-edge` / `--ink-soft`），省 6 行变量；
- `.slip__text:focus-visible` 与全局 `:where([role="textbox"])` 重复，只保留圆角。

压回 9.88 KB。**当时预算没动过。**

> 后续（2026-11-12）CSS 预算经裁决从 10 KB 提额到 **14 KB**：10 KB 的配额定于 R31 之前，
> 当时还没有双模变量体系；R31–R41 整套深浅色 + 聚焦环 + 横幅三档 + 细滚动条净增约 2.3 KB，
> 死守 10 KB 只会逼出"为指标牺牲可读性"的缩写。本文其余关于 10 KB 的描述是**当时的事实**，
> 保留不改。

## 五、这一阶段的方法学收获

视觉项原本只能靠 CDP 验，而本机 SAC 让"启动应用"变成一件不确定的事。这轮把**判定类逻辑**
从组件里抽出来（`ui/src/lib/status.js`），配 `tools/check-ui-logic.mjs`，不需要浏览器就能跑，
并且已接进提交钩子与 CI。后续视觉轮次会继续沿这条线：**能脱离 GUI 验的先脱离**，
剩下的（真正需要渲染的）才留给 CDP。
