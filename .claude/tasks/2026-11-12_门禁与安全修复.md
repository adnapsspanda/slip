### 0.2 对审查文档的修正（避免照着做过期工作）

这四条与源码不符，不能照单执行：

1. **第 7 条「purge 的逐字节保护只有一条单测」不成立。** `purge_removes_exactly_one_line_and_keeps_the_rest_byte_identical` 已经逐行比对删除前后的字节。真正缺的是**事务层自身的闭合断言**，不是测试。修法仍值得做，但优先级是 P2，不是 P1。
2. **第 4 条「只检查一个方向」不准确。** `check-ci-parity.ps1` 的 `$missingInHook` 确实检查了 CI→钩子方向。真正的问题是三点：`Where-Object { $_ }` 静默丢弃无法归一的步骤、`$hookOnly` 是空死代码、命令片段只比对 `workspace` 一处。修法按这三点来。

4. **第 11 条的 Enter 路径确实无害。** 真正有后果的是 Tab 路径与「切到另一条时 `void commitEdit()`」的丢弃草稿问题。修法要覆盖两处，不能只改 Tab。

## 1. 批次 0：门禁修复（半天，无行为改动）

**验收方式只有一个：各自故意破坏一条约束，确认退出码非 0，然后还原。** 这一步不做，后面所有「测试通过」都不算证据。

### 1.1 `tools/check-forbidden.ps1` 的 Include 匹配

现状：`$glob -replace '^\*',''` 把 `Cargo.toml` 原样留下，而匹配侧用 `GetExtension`（`.toml`），所以三处 `-Include @('Cargo.toml')` / `@('tauri.conf.json')` 永远不会命中。

修法：

- 把 Include 拆成两个集合：`*.ext` 进扩展名集合，普通文件名进精确文件名集合；出现 `?`、`[` 等复杂 glob 直接抛错，不静默降级。
- `Check-Forbidden` 增加 `-FileList`（默认 `Get-SourceIndex`）与 `-Quiet`，让自检能走真实代码路径。
- `-SelfTest` 增加端到端用例：临时目录写一个包含 `notify = "6"` 的 `Cargo.toml`，用 `-FileList` 调 `Check-Forbidden`，必须增加失败计数；再写一个不含违禁项的同名文件，必须不增加。
- 保留现有的三条正则正负样本用例。

破坏验证：临时在根 `Cargo.toml` 写 `notify = "6"`，跑脚本必须退出 1；删掉后恢复 0。SQLite 与 CSP 同理各验一次。

### 1.2 `tools/check-ui-logic.mjs` 退出判定位置

现状：第 612–615 行就 `process.exit`，其后第 618–662 行还有 14 条 `check(`（列表边界 4 条 + 对比度 10 条），永远不参与判定。

修法：

- 把 `if (failed > 0) { ... }` 与最终 `全部通过` 整体移到文件最后一行。
- 增加结构守卫：脚本读取自身源码，找到最后一次 `check(` 与退出判定的行号；若存在 `check(` 在退出判定之后，直接失败并打印行号。守卫本身也要有负样本自检（临时把一段 `check(` 移到末尾，必须退出 1）。

破坏验证：在文件末尾追加一条必失败断言，退出码必须为 1；删除后恢复 0。

### 1.3 `tools/mutation-audit.py` 复活

现状：`REPO = r"D:\Dev\simple-todo"`、`/mnt/d/...`、`wsl.exe -d Arch` 全硬编码，第一步就抛异常；`red = (code != 0) or (marker in out)` 把编译失败也算成「测试变红」。

修法：

- `REPO = Path(__file__).resolve().parents[1]`。
- 子进程直接 `cargo test -p <crate> --all-targets --offline`，`cwd=REPO`，参数用列表，不经过 shell，不经过 WSL 包装。
- 开始前先跑一次基线，基线不绿直接退出，不进入变异。
- 判据收紧：`"test result: FAILED" in out` 才算红；出现 `error[E` 或 `could not compile` 记为 `[INVALID]`（变异把代码写坏了）并计为审计失败，绝不记为 PASS。
- 恢复后核对逐字节一致（现有逻辑保留），最后再跑一次全绿。
- 同步更新文件头用法说明。

破坏验证：把任意一条用例的 `old` 改成不存在的锚点，审计必须报「锚点未匹配」并非零退出；再临时把判据改回宽松版，用一条编译错误变异确认会被标 `[INVALID]`。

### 1.4 `tools/check-ci-parity.ps1` 补全与收紧

现状：无法归一的步骤被 `Where-Object { $_ }` 静默丢弃；`$hookOnly = @()` 是死代码；命令片段只检查钩子 `--workspace` 一边。

修法：

- 补三条关口：`常量：死代码与前后端镜像`、`设计文档与代码同步`、`门禁对等性`。
- 未识别步骤默认 `[FAIL]`，由显式白名单放行。白名单按**原始步骤名**写，不按归一后的名字写：
  - 钩子：`通过`、`前端产物缺失或陈旧，先构建`（后者本来就归一到「前端构建」）。
  - CI：安装/缓存/工具链步骤、`Release 构建`、`Linux 外壳 Clippy`、`Linux 外壳构建`、`Linux 外壳单测`、`安装 Tauri Linux 构建依赖`、`逻辑层测试（domain / store / app）`、`逻辑层 Clippy`。
- 删除 `$hookOnly` 空数组；两个方向的差集都保留。
- 命令片段双向断言：
  - clippy：两侧都必须含 `--all-targets` 与 `-D warnings`。
  - 测试：两侧都必须含 `--workspace`。
  - 格式：两侧都必须含 `fmt --all` 与 `--check`。
  - 禁止清单：两侧都必须调用 `check-forbidden.ps1` 且带 `-SelfTest`。
- 每一类失败都累加，最后统一退出，不提前 `exit`。

破坏验证：临时从 CI 删掉一条 clippy 的 `--all-targets`，脚本必须退出 1；临时把钩子里的 `-SelfTest` 去掉，同样必须退出 1。

### 1.5 `-SelfTest` 接入钩子与 CI

`.githooks/pre-commit` 与 `.github/workflows/ci.yml` 的禁止清单调用都改为 `check-forbidden.ps1 -SelfTest`。脚本本来就会先跑完整扫描再自检，耗时增加不到 1 秒。

### 1.6 `tools/check-doc-sync.ps1` 扩两条

- 读取后 `TrimStart([char]0xFEFF)`，修掉 Windows PowerShell 5.1 的 `ConvertFrom-Json` 失败。
- 新增预算一致性断言：从 `check-bundle-size.ps1` 解析 `$cssLimit` / `$jsLimit`，与 `docs/handover.md`、`.githooks/pre-commit` 注释里的 KB 数字比对；不一致即失败。

## 2. 批次 1：数据安全（store）

### 2.1 彻底删除：备份失败必须拒绝执行

现状：`crates/slip-store/src/lib.rs:610-618` 备份失败只记 `Warning::BackupFailed`，然后继续删行。删成功了但备份没落地，前端却提示「已留备份」。

修法：`purge_archived` 在备份创建失败时直接返回 `StoreError::Io(kind)`，**不写主文件、不改内存状态**。清理旧备份（`prune`）失败仍只记警告——它不产生新的不可逆风险。前端 `purgeNotice()` 不加参数：后端拒绝后不存在「成功但备份失败」的组合，再加一个永远为 false 的参数是死代码。

测试：`purge_refuses_to_delete_when_backup_fails`，用 `fail_next_backup()`，断言结果 Err、文件逐字节不变、content_rev 不变。

变异验证：把拒绝分支改回只记警告，该测试必须红。

### 2.2 备份恢复：先校验，再备份，最后覆盖

现状：`lib.rs:841-847` 先 `fsops::backup(&path)`，而 `fsops::backup` 第一行 `read_bytes(path)?`；`inbox.md` 不存在时直接 NotFound，最需要恢复的场景反而恢复不了。非法名字也会先白烧一代备份。

修法顺序：

1. 校验名字并定位备份源，读出候选字节。新增 `fsops::read_backup(inbox, name) -> Result<Vec<u8>, IoKind>`，内部复用现有名字规则。
2. `doc::parse(&bytes)` 预检；有 `problems` 就返回新错误 `StoreError::BackupInvalid`，不碰当前文件。
3. 读当前内容：`Ok(current)` 写一代备份；`Err(NotFound)` **跳过备份继续**；其他错误返回。
4. `write_atomic` 覆盖，然后走 `reload()`。

`StoreError::BackupInvalid` 在 `map_store_error` 里映射为 `("invalidBackup", "备份内容无法解析，未恢复")`，`result_for_code` 归为 `Rejected`。

测试：

- `restore_backup_works_when_inbox_is_missing`：删掉 inbox，恢复后内容等于备份。
- `restore_with_an_invalid_name_does_not_consume_a_backup`：非法名字，备份数量不变。
- `restore_refuses_a_corrupt_backup_without_touching_inbox`：备份里写 `BAD!!`（现有 fake parse 的触发词）或构造坏记录，断言当前文件不变、结果 `BackupInvalid`。

变异验证：把「NotFound 跳过备份」改回无条件备份，第一条测试必须红。

### 2.3 彻底删除：事务层补逐字节闭合断言

现状：候选文档由行数组删一行构造，但事务层不验证「其余行原样」。已有单测在守，缺的是实现自身的断言。

修法：在 `purge_archived` 里，渲染前先构造期望行序列（`candidate.lines` 的 raw 拼接），与 `bytes` 比较；再断言该序列等于「原文档行序列删掉目标行」。任一不等就写诊断并返回 `Io(Other)`，不写盘。

测试：用测试专用 `DocOps`，把 `render` 换成「跳过 `LineKind::Other`」的实现，构造含普通行的归档文档，`purge_archived` 必须失败且文件不变。

变异验证：去掉新断言，该测试必须红。

### 2.4 成功提交后清空诊断

现状：`apply` 成功路径（`lib.rs:741-761`）与 `purge_archived` 成功路径（`:629-646`）都不清 `state.diagnostics`；一次回读闭包失败留下的错误会永久挂在横幅上。

修法：两条成功路径在 `state.bump()` 之后 `state.diagnostics.clear()`。失败路径不动。

测试：手动把 `state.diagnostics` 塞一条，调一次成功 apply / purge，断言快照诊断为空。

变异验证：删掉 clear，测试必须红。

### 2.5 回读闭包校验被修改行的 extras

现状：`doc.rs:753-773` 对被 patch 的行直接 `continue`，记录比较只看 `Slip`，不含 `Record::extras`。`rewrite_line` 的兜底分支一旦回归，用户手写的 `zz=9` 会静默消失。

修法：在跳过被修改行之前，比较原记录与新记录的 `extras`；不等返回新增的 `RoundtripError::ExtrasChanged { index }`。

测试：`verify_detects_extras_lost_on_a_modified_line`，构造带 `zz=9` 的原文档与丢键的候选字节，断言 Err。

变异验证：去掉 extras 比较，测试必须红。

## 3. 批次 2：前端生命周期

### 3.1 `pendingDone` 的失效条件

现状：`ui/src/App.svelte:46` 定义，只在「成功且快照追上」时删除（`:604-606`）；失败路径永久残留。之后用户按提示重新载入再点同一行，会发出一次「设为未完成」的 Noop。

修法：

- `ui/src/lib/queue.js` 新增纯函数 `keepPendingIntent(accepted, storedDone, targetDone)`：未接受 → false；快照已等于目标 → false；否则 true。
- `handleToggle` 的 `finally` 改用该函数；失败分支必定删除该条意图。
- `summon()` 增加 `pendingDone = {};`。
- 在 `tools/check-ui-logic.mjs` 补 3 条纯函数断言。
- 在 `AGENTS.md` 的状态生命周期表新增一行：`pendingDone` / 何时清（失败、快照追上、`summon()`）/ 漏掉后的症状（勾选要按两下）。
- 在 `crates/slip-app/tests/frontend_lifecycle.rs` 的 `summon` 断言列表加入 `pendingDone = {};`。

变异验证：删掉失败分支的删除，纯函数断言仍绿（它只测函数），所以**必须**再加一条源级断言：`handleToggle` 函数体中包含 `if (!keepPendingIntent(`。删掉该行，生命周期测试必须红。

### 3.2 编辑失败后的 Tab 与切换目标

现状：`commitEdit()`（`ui/src/lib/SlipList.svelte:227-248`）没有返回值；Tab 分支无条件 `commitEdit().then(() => beginEdit(...))`，失败时 `beginEdit` 又会 `void commitEdit()`，同一份草稿发两遍且被覆盖。

修法：

- `commitEdit` 返回 `boolean`：未改/取消 → true，后端接受 → true，失败 → false。
- Tab 分支：`if (!(await commitEdit())) return;` 之后才 `beginEdit(slips[target])`。
- Enter 分支同样按返回值决定是否 `refocusRow`（行为上的差异很小，但语义一致）。
- `beginEdit` 改为 `async`：切换目标前 `if (!(await commitEdit())) return;`，不再 `void commitEdit()`。所有调用点改为 `void beginEdit(...)` 或 `await`，避免未处理 Promise。

测试：`frontend_lifecycle.rs` 增加源级断言：Tab 分支包含 `if (!(await commitEdit())) return;`；`beginEdit` 的切换分支包含 `await commitEdit()`。变异验证：改回无条件调用，测试必须红。

### 3.3 损坏文件预览的只读性

现状：`handleKeydown`（`App.svelte:1006`）不检查 `preview`；弹窗打开且焦点在 `<pre>` 时，Ctrl+Z 会真的撤销后端内容，Ctrl+F 会在弹窗背后打开过滤框。

修法：

- `handleKeydown` 顶部加 `if (preview) return;`。
- 弹窗面板加 `tabindex="-1"`，打开后 `previewEl?.focus()` 再全选。
- `handleKeydownCapture` 在弹窗打开时拦截 `Tab`，防止焦点跑到弹窗背后。

测试：`frontend_lifecycle.rs` 源级断言 `handleKeydown` 函数体含 `if (preview) return;`。

### 3.4 撤销走串行队列

现状：`handleUndo`（`:945`）只用 `undoing` 布尔，绕过 `createSerialQueue`。toggle 在飞时按 Ctrl+Z，撤销会先到后端。

修法：`bridge.undo` 包进 `mutating.run(...)`，保留 `undoing` 防连点。注释写清「队列保证撤销排在已提交的变更之后」。

测试：`frontend_lifecycle.rs` 源级断言 `handleUndo` 函数体含 `mutating.run(`。

### 3.5 备份面板的异步竞态

现状：`toggleBackups`（`:684-695`）无代数保护；快速开→关→开时旧响应可能覆盖新结果，面板关闭后失败仍写 hint。

修法：加 `backupsToken` 自增；响应返回后校验 `token === backupsToken && showBackups` 才写 `backups` / `hint`。

测试：源级断言 `toggleBackups` 函数体含 `backupsToken`。

## 4. 批次 3：外壳

### 4.1 同步 IPC 的重 I/O 下放

`backup_list`（`src-tauri/src/lib.rs:421`）对每份备份完整 `doc::parse`；`vault_capacity`（`:613`）读整个 `inbox.md` 再解析。两者都是同步 `#[tauri::command]`，会在主线程执行。

修法：改为 `async fn`，函数体用 `tauri::async_runtime::spawn_blocking`，先把 `state.vault.clone()` 出来，再在闭包里读盘。`corrupt_files` / `corrupt_preview` / `vault_path` 保持同步（元数据或 64 KiB 上限）。

验收：`cargo clippy -p slip-shell --all-targets --offline -- -D warnings` 与 `cargo test -p slip-shell --lib --offline` 通过。这条没有行为测试，只能靠编译与人工确认调用点。

### 4.2 热键回落：状态诚实 + 落盘

现状：`switch_to_fallback` 双失败时只 warn，`ShellState.hotkey` 保留旧值，界面仍报旧键可用；成功切换也不写 `ui-state.json`，重启回默认。

修法：

- `hotkey.rs` 引入 `pub enum FallbackOutcome { Switched(String), RestoredOld(String), NoneRegistered }`；`switch_to_fallback` 返回 `Result<FallbackOutcome, String>`。解析失败/注销失败仍 Err；备选失败但旧键恢复成功返回 `RestoredOld`；两者都失败返回 `NoneRegistered`。
- `system.rs::switch_fallback_hotkey` 按三态处理：`Switched` 更新 `ShellState`、写偏好、刷新托盘；`RestoredOld` 保持状态并提示；`NoneRegistered` 把热键置空并刷新托盘，让 tooltip/`hotkey_status` 如实显示未注册。
- 写偏好：新增 `persist_hotkey(vault, key)`，用 `JsonPrefsStore::load_prefs` 读旧值、只改 `hotkey`、`save_prefs`；失败只 warn，不声称已保存。
- 启动注释「运行期不再写回」一并更新。

测试：

- `FallbackOutcome` 的纯映射测试（三态到「是否注册/文本」）。
- `persist_hotkey` 用临时目录写入后加载，断言 `hotkey` 等于新键；写失败路径不 panic（目录不存在）。
- `src-tauri/Cargo.toml` 增加 `[dev-dependencies] tempfile.workspace = true`（lock 已有）。

变异验证：把 `NoneRegistered` 分支改回「保持旧值」，对应三态测试或源级断言必须红（三态映射是纯函数，能直接红）。

### 4.3 启动 I/O 失败不再静默崩溃

现状：`lib.rs:757-768` `ensure_dir` 失败 `panic!`，外层 `.join().expect` 再 panic；Windows release 是 `windows_subsystem = "windows"`，错误只进 stderr，用户看到「双击没反应」。

修法：

- 线程内 `ensure_dir` 失败只 `tracing::error!`，继续构造 `MarkdownStore`（`startup_state` 会把读失败落成 Degraded + 诊断）。
- `.join()` 失败时回退：用同一路径构造 store + `Prefs::default()`，并记录错误，不 panic。
- 启动展示逻辑不动，窗口仍会显示，横幅显示诊断。

测试：`startup_with_unreadable_path_degrades_instead_of_panicking`——把 `inbox.md` 路径指向一个普通文件下的子路径，`startup_state` 必须返回 Degraded + 非空诊断。

### 4.4 单次提交少读一次全文件

`apply` 里 `read_for_conflict` 已读到整份字节，随后 `fsops::backup` 又读一遍。新增 `fsops::backup_bytes(path, &[u8])`，`backup()` 改成「读一次 + 调它」；`apply` / `purge` / `restore` 复用刚读到的字节。

测试：现有 `commit_ack_survives_backup_failure` 与 `purge_writes_a_backup_first` 必须继续绿；再加一条「backup_bytes 写入内容与当前文件一致」。

变异验证：把 `apply` 改回 `fsops::backup(&state.path)`，行为测试不会红——所以这条只做**性能证据**：改前/改后各跑一次 release 性能测试并记录数字，不用测试假装覆盖。

### 4.5 每行少一次分配

`doc.rs:176-204`：`build_parsed_line` 内部 `raw.to_vec()`，调用方再 `line.raw.copy_from_slice(...)`。改为构造时直接持有 raw，调用方不再复制。

验收：现有 `format_closure` 全部通过；release 性能数字与 4.4 一起记录。

### 4.6 损坏预览路径的符号链接

`guard_corrupt_path` 只 canonicalize 父目录，返回未规范化的 candidate。对最终路径 `canonicalize()` 后重新比对父目录，并 `is_file()`。

测试：临时 vault 内建正常文件 → 通过；建指向 vault 外的符号链接（`#[cfg(unix)]`）→ 拒绝；`..` 穿越 → 拒绝。
